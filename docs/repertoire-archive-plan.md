# Game explanations, repertoire, and archive jobs

1. Explain a selected game from its actual moves, final board, and available engine evidence. A loss question starts a review if needed and refreshes when ready.
2. Keep position results visible while exploring, with their original position and search profile labelled. Replay the engine line without editing the recorded game.
3. Scan every game in a pinned personal collection through a durable, resumable background queue. Retain missed advantageous moves as playable exercises, grouped by phase. Save attempts privately. Interactive engine work has priority.
4. Continue with available archive games after personal games. Display the source month and coverage; never call a historical sample the latest archive.
5. Discover official monthly archives and accept official PGN/torrent links. Queue an explicit month with a user-selected download ceiling. Download, verify, frame, and publish through the existing container pipeline, with durable status and pause/cancel controls.
6. Validate source behavior, database ownership, browser interactions, real games, and backup/restore in Docker. Preserve existing private records. Keep large archive tests opt-in.

The initial personal build is authorized to continue until paused. A complete library scan is a background operation, not a prerequisite for using exercises already found. Engine scores are bounded search estimates, not proof of a forced win. Phase labels use the documented material/ply heuristic. Automatic latest imports require explicit user configuration; the all-month backfill remains disabled.
